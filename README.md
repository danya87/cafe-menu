# Лабораторна робота №1

## Варіант

**5 — Меню кафе**

## Призначення програми

Консольна Java-програма читає записи меню кафе з текстового UTF-8 файла, перевіряє коректність кожного запису, пропускає помилкові рядки з повідомленням про номер рядка та причину помилки, обчислює підсумкові показники та формує звіт.

Результат виводиться у консоль та записується у текстовий файл.

## Формат вхідних даних

Кожний рядок має формат:

```text
name;category;price;weightG;prepMin
```

де:

- `name` — назва страви або напою;
- `category` — категорія;
- `price` — ціна;
- `weightG` — вага у грамах;
- `prepMin` — час приготування у хвилинах.

Приклад коректного запису:

```text
Борщ український;Основні страви;145.50;350;25
```

Приклад вхідного файла:

```text
Борщ український;Основні страви;145.50;350;25
Капучино;Напої;75.00;250;7
Сирники;Десерти;120.00;220;15
Вареники;Основні страви;помилка;300;20
Лимонад;Напої;60.00;-400;5

Салат овочевий;Закуски;95.00;180
```

Некоректні записи не завершують роботу програми. Для кожного такого рядка виводиться його номер та причина пропуску.

## Результати

Для коректних записів програма обчислює:

- кількість коректних записів;
- середню ціну;
- найбільшу вагу;
- найдовший час приготування.

Для наведеного тестового набору результат:

```text
Меню кафе — варіант 5
Коректних записів: 3
Середня ціна: 113.50
Найбільша вага: 350 г
Найдовший час приготування: 25 хв
```

## Файли за замовчуванням

Вхідний файл:

```text

```

Вихідний файл:

```text
out/report.txt
```

## Параметри командного рядка


`--input <файл>` — задає шлях до вхідного UTF-8 файла.

## Ієрархія MenuItem

`MenuItem` є спільним базовим типом для позицій меню.

Ієрархія має вигляд:

    MenuItem
    ├── Dish
    ├── Drink
    └── Dessert

У базовому типі зберігаються спільні поля:

- `name`;
- `category`;
- `price`;
- `weightG`;
- `prepMin`;
- `kind`.

Усі поля мають `private final`, setter-и відсутні.

Спільна валідація винесена до `MenuItem` і не дублюється у підтипах.

- `name` не може бути `null` або порожнім;
- `category` не може бути `null` або порожньою;

- `weightG` не може бути від'ємною;
- `prepMin` не може бути від'ємним;
- `kind` не може бути `null`.

## Підтипи

Реалізовано три конкретні підтипи:

- `Dish` — страва;
- `Drink` — напій;
- `Dessert` — десерт.

Кожний підтип успадковує спільний стан від `MenuItem` та має власну реалізацію поліморфного методу.

## MenuKind

Для типу позиції меню використовується enum `MenuKind`.

Він містить:

    DISH
    DRINK
    DESSERT

`MenuKind` використовується у предметній моделі та під час створення відповідного підтипу.

## Поліморфізм

У базовому типі `MenuItem` оголошено поліморфний метод:

    preparationCost()

Підтипи перевизначають його через `@Override`.

Реалізації:

- `Dish` — 30 % від ціни;
- `Drink` — 15 % від ціни;
- `Dessert` — 25 % від ціни.

Різні підтипи можуть зберігатися в одній колекції `List<MenuItem>`.

Поліморфний метод викликається через базовий тип без перевірки конкретного підтипу через `if` або `switch`.

## Фабричний метод fromCsv

Для створення позиції меню з CSV-рядка використовується статичний фабричний метод:

    MenuItem.fromCsv(String line)

Метод перевіряє кількість полів, виконує числові перетворення, визначає `MenuKind` та створює відповідний підтип.

Категорія `Напої` створює `Drink`.

Категорія `Десерти` створює `Dessert`.

Інші допустимі непорожні категорії, зокрема `Основні страви` та `Закуски`, створюють `Dish`, що зберігає сумісність із Lab 2.

## Рівність об'єктів

У `MenuItem` реалізовано узгоджені методи `equals()` і `hashCode()`.

Два об'єкти вважаються рівними, якщо:

- належать до одного конкретного підтипу;
- мають однакові значення предметних полів.

Різні підтипи не вважаються рівними лише через однакові значення полів.

Коректність `equals()` і `hashCode()` перевіряється за допомогою `HashSet`.

## Вибір спадкування

Для моделі використано спадкування, оскільки `Dish`, `Drink` і `Dessert` є різновидами `MenuItem`.

Підтипи мають спільний стан і правила валідації, але відрізняються поведінкою.

Такий підхід відповідає відношенню `is-a` та дозволяє обробляти різні позиції меню через один базовий тип.

## Sealed-ієрархія

У межах завдання із зірочкою `MenuItem` реалізовано як `sealed` базовий тип.

Дозволені підтипи:

    Dish
    Drink
    Dessert

Класи `Dish`, `Drink` і `Dessert` оголошені як `final`.

Для окремої допоміжної операції реалізовано вичерпний pattern-matching `switch`, який обробляє всі дозволені підтипи.

`switch` не дублює логіку `preparationCost()`, яка реалізована через поліморфізм.

## Record PriceWeight

Для допоміжного незмінного представлення ціни та ваги збережено record `PriceWeight`.

Він містить:

- `price`;
- `weightG`.

Під час створення `PriceWeight` перевіряється коректність ціни та ваги.

## MenuItem.Builder

Для поетапного створення об'єктів збережено `MenuItem.Builder`.

Builder підтримує:

- `name`;
- `category`;
- `price`;
- `weightG`;
- `prepMin`.

Метод `build()` визначає тип позиції та створює відповідний підтип `MenuItem`.

Builder не обходить перевірку інваріантів.

## Архітектура запуску

Для розділення відповідальності логіку запуску програми винесено в окремі класи:

    Main
    ↓
    ArgumentsParser
    ↓
    AppArguments
    ↓
    CafeMenuController
    ↓
    MenuItem та його підтипи

`Main` використовується лише як точка входу та передає керування іншим компонентам.

`ArgumentsParser` виконує розбір параметрів командного рядка.

`AppArguments` зберігає параметри запуску.

`CafeMenuController` керує основним процесом обробки даних.

## Відмінності від Lab 2

У Lab 2 одна позиція меню була представлена одним класом `MenuItem`.

У Lab 3:

- `MenuItem` став абстрактним базовим типом;
- створено `Dish`, `Drink` і `Dessert`;
- створено enum `MenuKind`;
- реалізовано поліморфний метод `preparationCost()`;
- різні підтипи обробляються через `MenuItem`;
- реалізовано `equals()` і `hashCode()`;
- рівність перевіряється через `HashSet`;
- `MenuItem` реалізовано як `sealed`;
- додано вичерпний pattern-matching `switch`;
- кількість автоматизованих тестів збільшено до 55.

Формат CSV та зовнішня поведінка програми не змінилися.
