# Лабораторна робота №1

## Варіант

**5 — Меню кафе**

## Призначення програми

Консольна Java-програма читає записи меню кафе з текстового UTF-8 файла, перевіряє коректність кожного запису, пропускає помилкові рядки з повідомленням про номер рядка та причину помилки, обчислює підсумкові показники та формує звіт.

Результат виводиться у консоль та записується у текстовий файл.

## Формат вхідних даних

Кожний рядок має формат:

```text
name;category;price;weightG;prepMin
```

де:

- `name` — назва страви або напою;
- `category` — категорія;
- `price` — ціна;
- `weightG` — вага у грамах;
- `prepMin` — час приготування у хвилинах.

Приклад коректного запису:

```text
Борщ український;Основні страви;145.50;350;25
```

Приклад вхідного файла:

```text
Борщ український;Основні страви;145.50;350;25
Капучино;Напої;75.00;250;7
Сирники;Десерти;120.00;220;15
Вареники;Основні страви;помилка;300;20
Лимонад;Напої;60.00;-400;5

Салат овочевий;Закуски;95.00;180
```

Некоректні записи не завершують роботу програми. Для кожного такого рядка виводиться його номер та причина пропуску.

## Результати

Для коректних записів програма обчислює:

- кількість коректних записів;
- середню ціну;
- найбільшу вагу;
- найдовший час приготування.

Для наведеного тестового набору результат:

```text
Меню кафе — варіант 5
Коректних записів: 3
Середня ціна: 113.50
Найбільша вага: 350 г
Найдовший час приготування: 25 хв
```

Вхідний файл:


Вихідний файл:

```text

```

## Параметри командного рядка

Програма підтримує:

```text
--help
--version
--input <файл>
--output <файл>
```

`--help` — виведення довідки.

`--input <файл>` — задає шлях до вхідного UTF-8 файла.

`--output <файл>` — задає шлях до файла звіту.

# Лабораторна робота №2

## Варіант

## Призначення програми

Консольна Java-програма обробляє записи меню кафе з UTF-8 файла.

У лабораторній роботі №2 рядкове представлення даних із Lab 1 замінено об'єктною моделлю. Один запис меню представлено класом-сутністю `MenuItem`.

Програма читає записи з CSV-файла, створює об'єкти `MenuItem`, перевіряє коректність даних, пропускає помилкові рядки з повідомленням про номер рядка та причину помилки, обчислює показники варіанта, виводить результат у консоль і записує звіт у текстовий файл.

Формат вхідних даних, предметні показники та зовнішній формат звіту залишилися сумісними з Lab 1.

## Формат вхідних даних

Кожний рядок має формат:

```text
name;category;price;weightG;prepMin
```

де:

- `name` — назва страви або напою;
- `category` — категорія;
- `price` — ціна;
- `weightG` — вага у грамах;
- `prepMin` — час приготування у хвилинах.

Приклад коректного запису:

```text
Борщ український;Основні страви;145.50;350;25
```

Вхідний файл за замовчуванням:

Вихідний файл за замовчуванням:

## Клас MenuItem

Клас `MenuItem` представляє одну позицію меню та містить поля:

- `name`;
- `category`;
- `price`;
- `weightG`;
- `prepMin`.

Клас є незмінним: він оголошений як `final`, усі поля мають `private final`, setter-и відсутні.

Під час створення об'єкта перевіряються такі правила:

- `name` не може бути `null` або порожнім;
- `category` не може бути `null` або порожньою;
- `price` має бути скінченним числом і не може бути від'ємною;
- `weightG` не може бути від'ємною;
- `prepMin` не може бути від'ємним.

## Фабричний метод fromCsv

Для створення `MenuItem` з одного CSV-рядка використовується статичний фабричний метод:

```java
MenuItem.fromCsv(String line)
```

Метод перевіряє кількість полів, виконує числові перетворення та передає отримані значення основному конструктору `MenuItem`.

Правила предметної валідації не дублюються: остаточна перевірка стану об'єкта виконується конструктором.

## Record PriceWeight

Для допоміжного незмінного представлення ціни та ваги використовується record `PriceWeight`.

Він містить:

- `price`;
- `weightG`.

Під час створення `PriceWeight` перевіряється коректність ціни та ваги.

## MenuItem.Builder

Для поетапного створення об'єктів реалізовано `MenuItem.Builder`.

Builder підтримує:

- `name`;
- `category`;
- `price`;
- `weightG`;
- `prepMin`.

Метод `build()` створює об'єкт через основний конструктор `MenuItem`, тому Builder не обходить перевірку інваріантів.

## Відмінності від Lab 1

У Lab 1 розбір CSV і перевірка значень виконувалися безпосередньо під час обробки рядків.

У Lab 2:

- створено клас-сутність `MenuItem`;
- валідацію перенесено до конструктора;
- розбір CSV перенесено до `fromCsv`;
- коректні записи зберігаються як об'єкти `MenuItem`;
- створено record `PriceWeight`;
- реалізовано `MenuItem.Builder`;
- розширено автоматизоване тестування.

Зовнішня поведінка програми не змінилася.
